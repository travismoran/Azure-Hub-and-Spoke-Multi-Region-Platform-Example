Negative control (implicit): the spokes have no direct peering, and before
the firewalls/UDRs existed the eus2 ILB was unreachable from wus3 - peering
non-transitivity means the only viable path is through both firewalls.

Also caught by this run: eus2 ILB initially stuck `<pending>` with
`AuthorizationFailed` on `subnets/read` → control-plane identity lacked
Network Contributor on the BYO VNet → fixed in terraform (35ba44d).

## Test assets

- Workload manifest: nginx 1.27-alpine + ConfigMap page + Service with
  `service.beta.kubernetes.io/azure-load-balancer-internal: "true"`;
  tolerations for `CriticalAddonsOnly` and spot taints (dev system pool is
  tainted, spot pool scales from zero).
- Test driver (recreate as needed):

```bash
#!/usr/bin/env bash
# Wait for eus2 ILB IP, then curl it from a wus3 pod.
EUS2=~/.kube/aks-demo-dev-eus2.yaml; WUS3=~/.kube/aks-demo-dev-wus3.yaml
until ILB_IP=$(KUBECONFIG=$EUS2 kubectl get svc hello-eus2 \
  -o jsonpath='{.status.loadBalancer.ingress[0].ip}') && [ -n "$ILB_IP" ]; do sleep 10; done
echo "ILB_IP=$ILB_IP"
export KUBECONFIG=$WUS3
kubectl run xregion-test --image=curlimages/curl --restart=Never \
  --overrides='{"spec":{"tolerations":[{"key":"CriticalAddonsOnly","operator":"Exists"},{"key":"kubernetes.azure.com/scalesetpriority","operator":"Equal","value":"spot","effect":"NoSchedule"}]}}' \
  --command -- sh -c "curl -sS -m 20 http://$ILB_IP/ && echo CURL_EXIT_OK || echo CURL_EXIT_FAIL"
kubectl wait --for=jsonpath='{.status.phase}'=Succeeded pod/xregion-test --timeout=180s
kubectl logs xregion-test && kubectl delete pod xregion-test
```
